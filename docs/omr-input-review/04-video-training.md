# 04 条件分支：视频选帧与混合数据微调

此文是后续执行方案。先完成首轮输入对比，再按剩余错误进入相应分支。视频处理与模型训练不是前面步骤的默认副作用。

## 选择方向

| 剩余主因 | 所需补充材料 | 执行入口 |
| --- | --- | --- |
| 背景随视频变化，有更清晰帧 | 原视频、时间段、固定谱面区域 | M1 |
| 单帧仍可读，模型持续认错 | 已核验难例、结构化原谱 | T0–T3 |
| 当前词表无法表达技巧 | 带清楚标记的例子、准确技巧语义 | T0 |
| tokens 正确而 GP 错 | 正确 tokens、错误 GP 与原图 | 修转换链，沿 V2 验证 |
| 原谱像素已不可读 | 更清晰来源或用户确认 | 优先补材料；不能生成猜测真值 |

## M1：同谱面选帧，之后才尝试融合

**必要材料**：可读取的本地视频，谱面出现时间段，用户确认的单系统区域。同一谱面必须持续出现且可对齐。

**操作**：

1. 从用户指定区间抽取少量候选帧，记录时间戳和视频来源组；初次可试 5–10 帧，间隔按画面停留时间确定，这不是固定算法门槛。
2. 排除换页、滚动、遮挡与谱面内容变化的帧。播放指示线或高亮是变化干扰，也要标记。
3. 按六线/固定区域对齐，先挑数字与技巧最清楚的帧，送现有对比工作台；检查是否已经减少错误。
4. 只有选帧仍不足且对齐可靠时，试多帧统计增强。原帧与融合图并行保留；融合导致细线消失或拖影时回退选帧。
5. 同一谱面的帧共享人工确认标签之前，核对内容完全一致；所有帧继承相同 sourceGroup 与用途。

**产物**：时间戳清单、候选帧、选中帧、可选融合图、与原截图的成对报告。

**完成条件**：帧与原视频可定位、同谱内容已确认、处理收益有真实核验；无收益也记录实验结论。未知背景和透明度不能保证从压平像素无损恢复。

## T0：冻结标签语义与训练范围

**必要材料**：剩余错误分组，当前词表，P.M./装饰音等缺口例子；用户明确指定本轮要支持的技巧。

**操作**：逐个定义符号的作用范围、附着音、连接对象、时值贡献、目标 GP 表达。已有 token 误识别与缺 token 分开处理。遇到风格歧义，给用户展示具体例子并确认。

新 token 的工作必须覆盖：标签规则、稳定 token ID、embedding/输出参数迁移、分支词表等相关元数据、解码约束、结构/时值校验、AlphaTex/GP 转换和回归例子。旧 token ID 保持兼容；旧候选通过明确迁移或版本分离处理。

**产物**：本轮标签规则、支持矩阵、必要的迁移与验证清单。

**完成条件**：每种技巧都有清楚图例、可表达的标签和可核验 GP；没有只扩词表却缺少下游支持的符号。

## T1：自动生成带真值的谱图

**必要材料**：可使用的结构化 GP/GPX/AlphaTex 等谱源、与 T0 一致的解析与渲染能力、背景素材。普通 MusicXML 若缺弦品信息，不能只按音高反推唯一指法。

**操作**：

1. 用少量谱片段贯通结构化内容 → tokens 与图片的配对。记录原谱、渲染器版本、字体/布局及标签版本。
2. 对每种目标技巧抽检：图片是否真的显示，标签是否附着正确。隐藏属性或渲染不支持的技巧不能直接作为图像监督。
3. 在确认的片段上变化字号、弦距、布局；再叠加背景/底板透明度、缩放、压缩与温和模糊，压平为 RGB，接近真实视频截图。
4. 任何裁切必须同步对应完整标签和上下文。只改变外观且未遮掉关键内容时可复用标签；不可读增强删除或另作拒识材料。
5. 覆盖独立音乐结构、技巧组合、两位数品和不同弦，不能仅给同一个片段重复换背景。

**产物**：可复现生成配置、图像与标签配对、来源/渲染/增强血缘、抽检报告。

**完成条件**：抽检中没有系统性图/标签错配；相同配置可复现；未支持符号有去向；才扩大生成数量。

## T2：划分数据并建立微调入口

### 首轮预算（估计，不是达标保证）

| 用途 | 起步量 | 规则 |
| --- | ---: | --- |
| 真实训练 | 300–800 个独立系统 | 完整人工核验，覆盖真实错误分布 |
| 真实验证 | 约 100 个独立系统 | 选参数与 checkpoint |
| 真实测试 | 150–250 个独立系统 | 最终验收，不参与迭代调参 |
| 合成训练图 | 2,000–5,000 张 | 同时报告独立基础片段数量与增强倍数 |

B1 的开发材料可以进入训练，但不能再充当独立测试。每个稀缺技巧同时统计独立例子、出现次数与组合，不只报总张数。

**操作**：

1. 按原曲/视频/谱源分组后划分集合，再做增强；同源不同帧、不同渲染、近重复谱全部留在同一集合。来源不明的重复候选先核查。
2. 导出训练数据时交叉检查候选状态与用途：仅取当前有效、标签兼容、用途允许的记录；排除 superseded 和验证/测试来源。
3. 统计标签长度和未知 token。当前编码有截断行为，改为显式检查；超长样本调整完整小节边界或模型长度方案，保留相关上下文。
4. 当前本地训练脚本没有完整 OMR checkpoint 的加载入口；新增权重加载与配置兼容检查。`--pretrained-encoder` 不是继续当前完整 OMR 模型训练。
5. 同词表微调与扩词表迁移分别验证。先用小批数据检查输入、损失、梯度和保存/加载，再做正式实验。
6. 先测实际设备的显存/内存、单步耗时，再选 batch size 和精度；不照搬原始训练配置。CPU 推理可用不代表训练成本可接受。

**产物**：数据版本、分组划分、导出清单、真实微调命令、短跑日志与可加载 checkpoint。

**完成条件**：来源无交叉、无静默截断/未知标签、旧模型被实际加载且兼容性已验证、短跑产物可推理。训练命令完成后再记入文档，当前没有可直接运行的微调命令。

## T3：小步微调、验证与错误回流

**必要材料**：T2 产物、固定验证集、原模型基线、独立输出目录。

**操作**：

1. 从现有 checkpoint 开始，混合合成难例、真实核验例和正常清晰例。采样比例、学习率与冻结策略作为实验配置，不预设某个比例必然最优。
2. 可短暂冻结骨干稳定新参数，再低学习率联合训练；背景域适应需要验证视觉部分是否也应更新。
3. 用验证集选 checkpoint 和停止时机，按 03 文档检查弦品、节奏、技巧及人工修正成本，保留原模型用于回归。
4. 分析剩余错误，优先补不同来源的难例与稀缺技巧。模型高置信预测仍是候选，经过核验才成为真值。
5. 固定最终方案后只用独立测试集验收。新模型放独立目录，验证通过再决定工作台采用哪个版本，保留回退路径。

**产物**：模型/数据/配置版本、训练与验证日志、最终独立测试报告、错误回流清单。

**完成条件**：明确报告真实提升与退化；候选模型和当前使用模型分开；不以 loss 下降或 GP 可打开替代识别验收。
