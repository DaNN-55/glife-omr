# 02 输入处理、对比识别与记录

进入条件：B0 已完成，有至少几个已核验样本可验证流程；正式效果验收仍需要 B1/B2 的代表性基线。

## I1：生成并展示实际模型输入

**必要材料**：原图；`guitar_omr_dataset_smoke.py` 的 `load_image_tensor` 与推理调用路径；前端 `createModelInputImage`。

**操作**：

1. 跟踪从上传到张量的完整路径。当前前端 Canvas 是模拟预览，后端 Pillow 才执行实际预处理。
2. 让后端保存实际进入推理的灰度像素画布，前端展示该产物。张量归一化可用元数据描述，预览图应与归一化前像素一致。
3. 原图、处理图、模型输入分别标识。生成预览不应重复执行不同的缩放流程；从同一次处理结果获得推理输入和预览。
4. 对上传 PNG/JPEG/WebP 检查路径一致性；真正含 alpha 的文件与视频背景已压平的截图分开处理。若统一 alpha 合成方式，记录预处理版本并同时用于训练素材和推理。
5. 用像素/张量对应检查证明“展示的就是使用的”，再用真实图片人工查看数字可读性。

**产物**：实际输入图片、尺寸与预处理版本、工作台预览。

**完成条件**：前端不再用重建图冒充实际输入；后端推理与预览来自同一处理结果；历史没有该产物时明确显示未保存，而不是补造证据。

## I2：六线定位、裁切确认与回退

**必要材料**：清晰谱、带背景谱、倾斜谱、技巧超出六线区域的谱；每类至少一个可人工判定的例子。

**操作**：

1. 先做保守的六线定位：检查近等距、共同方向与重叠横向范围，排除背景中的孤立水平线。优先复用已有依赖；若需要 OpenCV，再说明必要性并加入可复现依赖配置，不手写庞大的检测框架。
2. 输出建议区域、弦线位置和定位状态。第一版只处理单系统，不承担整页自动分谱。
3. 按检测角度校正轻微倾斜，裁切时保留上下技巧与必要小节上下文；余量根据弦距表达，具体初值由开发样本验证。
4. 工作台展示建议区域，支持手动调整和恢复原图。允许定位失败后手动裁切，不要求失败图片必须通过检测。
5. 记录裁切矩形、坐标参照、旋转角与处理顺序；确认后另存处理图。涉及旋转时保留坐标映射，确保重开可复现。
6. 第一版人工确认裁切后再识别；只有后续证据充分才考虑自动采用建议区域。

**产物**：规范裁切图、参数、定位结果、人工确认状态。

**完成条件**：已核验图片中六根弦和完整技巧均被保留；失败可回退；同图同参数产物一致；原图不被覆盖。自动建议有漏裁时记录失败而非计成功。

## I3：原图/裁切图对比与可追溯保存（首轮交付）

**必要材料**：I1/I2 产物；现有 `run_inference`、`find_reusable_inference`、`record_inference`、审核自动保存与离开保护的调用链。

### 操作与界面

1. 保留普通单次识别入口；增加按需“对比识别”，首轮只运行原图与确认后的裁切图。
2. 两个版本采用同一 checkpoint、解码配置和长度限制。按现有执行能力顺序处理，显示当前版本与取消/失败状态，不建立新任务队列。
3. 显示每个版本的图片、tokens、谱面与耗时。差异先定位到小节/token；模型没有音符坐标时不声称能在原图框出错音。
4. 用户选择一个结果作为人工修正起点，切换结果经过现有未保存编辑保护。原始预测保持不可变，修正结果单独保存。
5. 某版本失败时保留其他已完成结果；状态写明失败/未完成，不把上次成功结果显示成这次结果。
6. 复用现有历史记录能力，重开后能恢复版本、选择和审核结果。

### 最小记录契约（待实现）

| 内容 | 要求 |
| --- | --- |
| 原始样本关联 | `sampleId`、原图哈希、来源组；同一原图的版本可追溯 |
| 处理版本 | 版本 ID、处理方法版本、参数、处理图路径及哈希 |
| 模型输入 | 实际输入路径/哈希、维度与预处理版本 |
| 预测 | 现有 record ID、模型/词表哈希、解码配置、状态与耗时 |
| 比较 | 参与版本、分歧位置、选中版本；没有选择时保持空 |
| 人工修正 | 附着到正确记录的修正 tokens 与审核信息，沿用现有候选更新规则 |

可以增加一个简单比较清单引用现有预测记录，不必重写全部记录存储。旧历史缺字段时按旧单图记录打开；补关联须可恢复且不能改写原始预测。

**缓存规则**：查缓存的输入必须是实际送入模型的处理结果。预处理版本或影响推理的上下文改变时重新判断有效性；原图哈希相同不代表处理版本相同。内容相同的模型输入可以复用预测，但保留各自处理来源。缓存命中仍应保留该预测的警告，不能返回空警告伪装全部通过。

**候选规则**：对比运行本身只增加预测证据。保存人工结论才沿当前流程产生候选；图像真的改变且仍符合相同完整标签时，可作为后续增强数据，但用途、来源和标签关联必须明确。不能为了比较自动复制训练条目。

**产物**：对比入口、两份可追溯预测、历史重开、选择与修正记录。

**完成条件**：改裁切后不误用原图缓存；重开显示正确版本；失败不丢成功产物；切换/重新识别/离开不覆盖未保存修改；旧历史仍可读。用记录测试覆盖关联/缓存变化，用真实浏览器检查切换与保存。

## I4：温和增强（首轮之后）

**必要材料**：B2 基线，已完成的对比能力，背景/低对比样本。

**操作**：从现有 Pillow 处理能力开始，只增加一个温和增强候选；方法和参数固定后批量比较。先验证对比度或去阴影，避免叠加许多不可解释变换。原图与裁切版继续保留；细线、推弦箭头、小音符和两位数数字作为重点复核对象。

合成退化图可作小检查，但真实背景图决定是否采用。处理失败保留原因；不得通过删掉失败样本改善报告。

**产物**：第三个候选版本、参数版本与成对评测报告。

**完成条件**：按 03 文档比较覆盖全部样本与场景；证据不足则保留为实验选项，不默认启用。增强是否采用与“这项实验是否完成”分别记录。
