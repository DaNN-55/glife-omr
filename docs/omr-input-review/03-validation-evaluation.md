# 03 结构提示与版本验收

## V1：产生具体复核提示

**必要材料**：预测 tokens、已知拍号/调弦等上下文、原图与版本差异；人工确认的正常/异常例子。

**操作**：

1. 先复用词表与 token 结构检查，再增加确实能可靠判断的语义检查。读取所有相关调用者，保证审核入库与展示使用兼容规则。
2. 输出问题类型、相关小节/token、触发原因与覆盖范围，而不是一个总“可信度”。
3. 时值按实际拍号计算，覆盖附点、连音和休止。拍号未知、弱起规则未确定、多声部或缺失装饰音语义时，相关检查输出“无法判断”。
4. 技巧须检查附着对象及其连接关系；词表缺口、转换尚未支持、原图不可读分开显示。
5. 将不同版本的分歧标为复核线索。几何检查需要音符坐标时，说明当前没有该证据，不能从 token 弦号循环证明自身正确。
6. 提示不自动改谱。用户仍可导出候选 GP，并看到未解决问题；无法解析的内容说明具体失败原因。

**显示状态**：`未发现已知问题`、`需要复核`、`当前无法判断`。第一种只表示已有检查未发现问题，不表示人工确认正确。

**产物**：问题列表与覆盖说明、工作台提示、最小正常/异常检查。

**完成条件**：已知异常触发对应提示；支持范围内正常例子不误报；未支持语义不被强行当错误或正确；原始预测保持不变。

## V2：评估与采用决定

### 必要材料

同一批核验标签、同一模型/解码设置下的原图与候选结果、场景分组、失败清单。首次正式发布前另准备未参与参数调整的同类真实样本，按来源组隔离。

### 指标口径

| 指标 | 如何计算/核验 | 必须说明的边界 |
| --- | --- | --- |
| 弦品事件 | 以小节/声部/节拍位置和音符事件对齐，报告精确弦品匹配与漏音/多音 | 对齐规则固定；和弦内部顺序先规范化；歧义单列 |
| 时值 | 已对齐事件/节拍的时值正确数与总数 | 未对齐、未支持节奏单列，不能从分母消失 |
| 技巧 | 类型、参数、起点/终点或覆盖音符均正确 | 单个技巧 token 出现不等于连接关系正确 |
| 小节完整正确 | 弦品、节奏、支持技巧全部与真值一致的小节比例 | 真值有缺口的小节标为不可全量评分 |
| 结构与转换 | 解析成功、小节规则提示、GP 转换问题 | 这是工程可用性，单独报告，不替代识别正确率 |
| 人工修正时间 | 从开始复核到确认完成的用时，记录暂停 | 同谱反复看有记忆效应，交错顺序并说明样本量 |
| 推理成本 | 实际推理耗时、对比总耗时、失败数 | 缓存命中分开报告 |

初版若只能可靠做序列对齐，先明确该口径及歧义，不宣称完成节拍级指标。技巧关系尚不能评分时保持“未实现”，由人工核验补充，不用 token 相似度代替。

### 评估流程

1. 用开发样本发现问题和选择处理参数，固定待验收配置、模型与代码版本。
2. 成对比较同一张图，列出改善、持平、退化、失败/无法评分；汇总各场景，不能只给平均分。
3. 人工复查所有退化与新失败，确认原因是裁切、视觉处理、模型输出还是转换。
4. 正式效果验收使用未参与调参的来源组；若看到验收集后修改参数，该集转为开发资料，另留新的独立验收样本。
5. 记录选择：默认启用、保留手动选项、回到前一版本。没有预先约定数值目标时不临时挑一个有利指标宣布成功；报告实数后由用户判断是否满足使用目标。

### 首轮交付的硬性检查

- 原图完整保存，处理图及模型输入可追溯；重开可复现裁切与比较。
- 单次识别保持可用；对比失败能保留成功项；缓存与所选版本一致。
- 人工修正不被版本切换、后台返回或重新识别覆盖；旧记录仍可读。
- 清晰谱、背景谱、技巧超界谱、定位失败谱均有真实操作证据。
- 所有纳入试验的样本在报告中有去向；退化和不可评样本可定位。

这些条件证明功能交付。真实准确性提升须由上述成对报告单独证明，材料不足时只完成工程交付。

### 与改动相称的验证

修改记录/服务后运行已有两个 unittest 文件；图像变换、解析与缓存关联新增少量有判别力的检查。界面用实际浏览器走上传、裁切、对比、编辑、切换、失败、重开和导出；GP 用可读取它的现有工具检查，并对照原图复核技巧。

测试命令和结果写进度记录，浏览器/GP 验收附样本 ID。自动测试通过不替代真实图片验收，也不要求为了纯文档改动运行模型训练。

**产物**：本目录下的阶段报告，列代码版本、数据清单版本、配置、逐类统计、退化原因、采用决定；完整大产物位于实验根目录。

**完成条件**：每个采用决定有对应证据，未完成的评分或操作明确列出，下一步只针对剩余主因展开。
