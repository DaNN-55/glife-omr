## B1：收集样本并确认真值

### 必要材料与数量

首轮目标是 30–50 个独立单系统谱面。建议每个主要场景至少 5 个：清晰数字谱、复杂背景、半透明视频叠层、技巧密集谱。一个样本可同时属于多个场景；相邻帧不增加独立样本数。优先覆盖多个原曲与来源。

每个样本最少准备：原始图、来源组、场景、人工可确认的谱面内容。推荐同时提供截图时间点、局部放大图或原始 GP/PDF。来自视频时保存同一谱面停留的片段或原视频路径，不要求现在剪辑整段视频。

| 材料 | 用户如何准备 | Agent 如何处理 |
| --- | --- | --- |
| 原图 | 保留原分辨率，含完整六线和上下技巧标记 | 原样保存并计算哈希，后续处理另存 |
| 来源 | 说明原曲/视频/文档，给本地路径或可核对标识 | 建来源组；不同文件名不一定是不同来源 |
| 正确内容 | 可以给正确 GP，或说明具体小节的正确音符/技巧 | 转成当前可表达的 tokens，再与原图核验 |
| 不确定内容 | 标明小节、弦、疑似品位或技巧 | 写入疑点清单，不强填真值 |
| 结构化原谱 | 有则提供，没有不阻塞图片路线 | 检查是否与截图同版本；能直接使用时记录直接导入路线 |

PDF/SVG 只有图形时仍不等于完整音乐语义。音频可辅助判断，但同音可能对应不同弦品，不能单凭音高生成弦品真值。

### 建议的本地组织

下列路径是待建立的实验布局，不是现有工具接口：

```text
artifacts/omr-input-review/
  samples/<sample-id>/original.png
  samples/<sample-id>/reference.tokens.txt
  samples/<sample-id>/review-notes.md
  samples.json
  runs/<run-id>/
```

视频用本地路径引用即可；原图扩展名保持真实格式。`samples.json` 第一版可以由 Agent 维护，不需要先做素材管理界面。

### 样本清单的最小字段

以下为新实验清单的设计，不能直接替换现有训练 manifest。

| 字段 | 含义与规则 |
| --- | --- |
| `sampleId` | 稳定 ID，一个独立谱面一个 ID |
| `sourceGroup` | 原曲/视频/同源谱组，用于防止数据跨集合泄漏 |
| `originalPath`、`originalSha256` | 相对实验根目录的原图路径与内容哈希 |
| `scenes` | 场景数组，用于分组报告 |
| `purpose` | `development`、`validation`、`test` 或 `train`；首轮通常为 development |
| `referencePath` | 人工确认 tokens 的路径；未确认时允许空 |
| `reviewStatus` | `pending`、`verified`、`unreadable`、`schema_gap` |
| `context` | 可确认的拍号、调弦、变调夹、小节范围；未知明确为空 |
| `gaps` | 无法表达/无法辨认的局部位置及原因 |
| `recordIds` | 与现有工作台识别记录的关联，可为空 |

### 确认流程

1. 检查原图是否完整，有无被剪断的技巧、缺弦、漏小节。重复图关联到同一来源。
2. 用原图运行当前模型，只把输出当修正起点。用户或熟悉吉他记谱的人逐小节确认弦、品、节拍、技巧与连接目标。
3. 把支持的内容写成完整 tokens，生成预览，对照原图，再导出 GP 抽查转换。预览与原图不符时区分识别和转换问题。
4. 若存在词表缺口，在疑点记录中保留原谱语义。完整真值不足的样本不计入整谱正确率；可评的局部必须明确评分范围，技巧缺口不能计为正确。
5. 对容易混淆的样本再核验一次；无法确认时给用户具体问题，不自行猜测。

**当前工作台注意事项**：人工结论保存请求带 `includeTraining: true`，会进入候选流程；不要假定存在“仅保存评测标签”的开关。首轮评测真值可单独放实验目录。已进入候选的验证/测试来源仍须由实验用途清单在训练导出时排除；现有候选 manifest 本身不提供这种隔离保证。

**产物**：样本清单、已核验标签、来源分组、未解决疑点。

**完成条件**：每张图都有来源/场景/用途；所有用于评分的标签均已核验；不可读和词表缺口有明确位置。30–50 是实验预算，不是准确率门槛；数量不足须报告覆盖缺项。

## B2：建立可重复的批量基线

**必要材料**：B1 中已核验的样本、固定模型与解码配置、可重复读取的样本清单。

**操作**：

1. 阅读 `scripts/evaluate_omr_ab.py` 和上游 token 语法。移除固定 17 音/3 结果、固定 4/4 的假设，输入改为多个样本各自的正确 tokens 与预测。
2. 核对附点、连音、休止、和弦、死音、拍号变化等的解析范围。已支持符号正确计算；未支持情况标为无法评分，不能静默忽略。
3. 明确弦号约定：模型弦序和 GP 弦序转换只做一次；当前转换使用 `7 - string`。所有评估双方先归一到同一种约定。
4. 用真实原图运行固定基线，保存预测、输入、耗时与配置。缓存复用单独记录，缓存响应耗时不当作推理耗时。
5. 按 03 文档的指标输出逐样本结果及分组摘要。对齐歧义单独标记，避免漏一个音造成后续全部被误判。
6. 为评估器保留小型可运行检查：完全相同、少音/多音、弦错/品错、附点/连音、空预测、未知上下文等；按实际实现的分支选择最少但有效的例子。

批量命令尚未实现。本步骤完成后，将真实可运行命令及参数写入进度记录，不用示例命令伪装可用工具。

**产物**：基线 run 目录、逐样本差异、场景摘要、评估覆盖说明。

**完成条件**：同配置重跑评分一致；空结果不会崩溃或被算成满分；所有分母与未评分数量明确；可定位每一个差异对应的原图和标签。
